# 网络资产发现：严格主机探活

启用主机探活时，仅已确认可达的主机进入端口扫描。未知、解析失败及当前路径不可达的主机均跳过，不自动扩大扫描范围。关闭主机探活时，保留直接扫描输入目标的行为。

## 探活顺序

- 显式指定端口（含 URL 端口）的主机：仅使用指定端口；混合输入中显式端口同样优先。
- 普通主机：Java 节点先执行 `InetAddress.isReachable(800)`。它是尽力可达性检测，结果来源记为 `java-reachability`，不声称使用了 ICMP。
- 未确认时按顺序 TCP 补探：第一轮 `443,80,22,445,3389`，再尝试第二轮 `135,8080,8443`。其他类型节点直接执行 TCP 补探。
- TCP 连接成功或明确拒绝均确认可达；任一命中立即结束该主机后续探活。
- 全部 TCP 探测均为 DNS／无路由错误时归类为解析或路径异常；其余未确认结果归类为未知。

## 调度与结果

每个节点任务以主机为目标，主机内部逐个执行原子探测；同一主机同时仅有一个探测，低于两个的上限。不同主机共享节点并发预算，默认至多 256，PHP 节点受其进程容量约束。暂停、背压时保存主机及探测游标并归还执行线程；恢复后继续，停止后丢弃迟到结果。

同一工作流中，复用扫描范围内探活已获得的开放／明确拒绝结果，避免重复连接。范围外结果仅作可达性证据；超时结果不复用为确定结论。复用观测标记 `probeSource=reachability-cache`，同时保留原始探活观测。

探活进度按已处理主机数计算。任务与持久化阶段快照保留可达、未知、解析或路径异常、待确认及已跳过数量。无可达主机时，下游阶段以 `NO_REACHABLE_HOSTS` 跳过，任务正常结束。

## 部署

节点组件有协议和实现更新。重新构建后端及 Java payload，重启后端，并在主机设置中重新加载 `NetworkProbeComponent`，然后创建新扫描。已有历史任务不会自动重跑。
